## One-time Setup

### Install clusterctl
```bash
curl -L https://github.com/kubernetes-sigs/cluster-api/releases/download/v1.12.3/clusterctl-linux-amd64 -o clusterctl
sudo install -o root -g root -m 0755 clusterctl /usr/local/bin/clusterctl
clusterctl version
```

### Install clusterawsadm
```bash
curl -L https://github.com/kubernetes-sigs/cluster-api-provider-aws/releases/download/v2.10.1/clusterawsadm-linux-amd64 -o clusterawsadm
chmod +x clusterawsadm
sudo mv clusterawsadm /usr/local/bin
clusterawsadm version
```

### Bootstrap IAM (run once per AWS account)
```bash
aws-export
clusterawsadm bootstrap iam create-cloudformation-stack
```

## Create Cluster

### Step 1 — Provision VPC with Terraform
```bash
cd stable_us-east-2_mgmt-cluster_ajayshandbook/

terraform init
terraform apply
```

Terraform creates:
- VPC (`10.0.0.0/16`) tagged for CAPA discovery
- Public subnets in `us-east-2a` and `us-east-2b`
- Internet Gateway + route tables
- `capi_cluster.yaml` — rendered with real VPC and subnet IDs

Check outputs:
```bash
terraform output vpc_id
terraform output public_subnet_ids
```

### Step 2 — Start kind management cluster
```bash
kind create cluster
```

### Step 3 — Export AWS credentials
```bash
aws-export
```

### Step 4 — Initialize CAPA on the management cluster
```bash
clusterctl init --infrastructure aws
```

### Step 5 — Apply the generated CAPI manifest
```bash
kubectl apply -f capi_cluster.yaml
```

`capi_cluster.yaml` is auto-generated by Terraform and already contains the correct VPC ID and subnet IDs.
The `AWSCluster` resource references them as:
```yaml
spec:
  network:
    vpc:
      id: vpc-xxxxxxxx          # Terraform-managed VPC
    subnets:
      - id: subnet-xxxxxxxx     # Terraform-managed public subnet (us-east-2a)
      - id: subnet-yyyyyyyy     # Terraform-managed public subnet (us-east-2b)
```

### Step 5a — Install Calico CNI
Nodes will stay `NotReady` without a CNI. Install Calico immediately after applying the manifest
(matches the `192.168.0.0/16` pod CIDR configured in the cluster):
```bash
# Switch to workload cluster kubeconfig first
clusterctl get kubeconfig mgmt-cluster > workload-kubeconfig.yaml
export KUBECONFIG=workload-kubeconfig.yaml

export KUBECONFIG=~/work/github_repos/infrastructure/04-clusterapi_aws/stable_us-east-2_mgmt-cluster_ajayshandbook/workload-kubeconfig.yaml

kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.3/manifests/calico.yaml
```

### Step 5b — Verify CCM is running on the workload cluster
The `crs-ccm` ClusterResourceSet deploys the Cloud Controller Manager automatically.
Without CCM, nodes will never get their `spec.providerID` and CAPA will stall.

Check it's running (switch to workload kubeconfig):
```bash
kubectl get pods -n kube-system -l k8s-app=aws-cloud-controller-manager
```

If no pods appear, manually apply it from the management cluster ConfigMap:
```bash
KUBECONFIG=~/.kube/config kubectl get configmap cloud-controller-manager-addon \
  -n default -o jsonpath='{.data.aws-ccm-external\.yaml}' \
  | kubectl --kubeconfig workload-kubeconfig.yaml apply -f -
```

### Step 6 — Watch cluster status
```bash
export KUBECONFIG=~/.kube/config
clusterctl describe cluster mgmt-cluster
kubectl get cluster
kubectl get kubeadmcontrolplane
```

## Refresh Expired SSO Credentials

SSO tokens expire after ~1 hour. The CAPA controller will log `RequestExpired` errors and
`VpcReconciliationFailed` when this happens — even though the clock is correct, an expired
STS session token causes AWS to reject all API calls.

> **Important:** Always `source aws-export.sh` (not `./aws-export.sh`) so the env vars
> persist in your current shell for the subsequent `kubectl patch` command.

```bash
# 1. Get fresh SSO credentials (source, not execute)
source aws-export.sh

# 2. Verify credentials are working
aws sts get-caller-identity --profile awsadmin

# 3. Patch the CAPA credentials secret with the fresh token
kubectl -n capa-system patch secret capa-manager-bootstrap-credentials \
  --type='json' \
  -p="[{\"op\": \"replace\", \"path\": \"/data/credentials\", \"value\": \"${AWS_B64ENCODED_CREDENTIALS}\"}]"

# 4. Verify the secret was updated (access key should match aws-export output)
kubectl -n capa-system get secret capa-manager-bootstrap-credentials \
  -o jsonpath='{.data.credentials}' | base64 -d | grep aws_access_key_id

# 5. Restart the CAPA controller to pick up new credentials
kubectl -n capa-system rollout restart deployment capa-controller-manager

# 6. Watch it recover
clusterctl describe cluster mgmt-cluster
```

## Delete Cluster (follow order to avoid orphaned AWS resources)

```bash
# 1. Ensure credentials are fresh before starting deletion
source aws-export.sh
export AWS_B64ENCODED_CREDENTIALS=$(clusterawsadm bootstrap credentials encode-as-profile)
kubectl -n capa-system patch secret capa-manager-bootstrap-credentials \
  --type='json' \
  -p="[{\"op\": \"replace\", \"path\": \"/data/credentials\", \"value\": \"${AWS_B64ENCODED_CREDENTIALS}\"}]"
kubectl -n capa-system rollout restart deployment capa-controller-manager

# 2. Delete workload cluster FIRST — cleans up EC2 instances, NLB, security groups
#    NOTE: CAPA does NOT delete the VPC/subnets since they are Terraform-managed (tagged "shared")
kubectl delete cluster mgmt-cluster

# 3. Watch deletion progress
watch clusterctl describe cluster mgmt-cluster
```

> **If deletion stalls** with `VpcReconciliationFailed` (SSO token expired mid-deletion):
> ```bash
> source aws-export.sh
> export AWS_B64ENCODED_CREDENTIALS=$(clusterawsadm bootstrap credentials encode-as-profile)
> kubectl -n capa-system patch secret capa-manager-bootstrap-credentials \
>   --type='json' \
>   -p="[{\"op\": \"replace\", \"path\": \"/data/credentials\", \"value\": \"${AWS_B64ENCODED_CREDENTIALS}\"}]"
> kubectl -n capa-system rollout restart deployment capa-controller-manager
> ```
> CAPA will automatically resume deleting NLB and security groups once credentials are refreshed.

```bash
# 4. Confirm all CAPI resources are gone
kubectl get cluster   # should return "No resources found"

# 5. Verify no EC2 instances remain in AWS
aws ec2 describe-instances \
  --filters "Name=tag:sigs.k8s.io/cluster-api-provider-aws/cluster/mgmt-cluster,Values=owned" \
  --query "Reservations[*].Instances[*].InstanceId"

# 6. Delete the kind management cluster
kind delete cluster

# 7. Destroy Terraform-managed VPC (only after CAPI cluster is fully deleted)
cd stable_us-east-2_mgmt-cluster_ajayshandbook/
terraform destroy

# 8. Unset AWS credentials
aws-unset
```

> WARNING: Never delete the kind cluster before running `kubectl delete cluster`.
> The CAPA controller will be gone and EC2/ELB resources will be orphaned, costing you money.

> NOTE: Because the VPC is tagged `kubernetes.io/cluster/mgmt-cluster: shared` (not `owned`),
> CAPA will **not** delete it. The VPC is only destroyed by `terraform destroy`.

## File Structure

```
stable_us-east-2_mgmt-cluster_ajayshandbook/
├── locals.tf              # Project config: naming, CIDRs, cluster settings
├── providers.tf           # AWS (awsadmin profile) + local providers
├── vpc_main.tf            # VPC, subnets, IGW, route tables
├── outputs.tf             # Exports vpc_id and public_subnet_ids
├── capi_manifest.tf       # Renders capi_cluster.yaml from template
├── capi_cluster.yaml.tpl  # CAPI manifest template
└── capi_cluster.yaml      # Generated after terraform apply — apply with kubectl
```
